Establish the Hall Branch Lifecycle

Formalize how a Work matures through Branch lineage, Office review, execution, Trace, and institutional-state return so the Hall exposes real participable work rather than repository endpoints alone.

  • Lifecycle state: proposed
  • Flow state: awaiting architecture review
  • Current Office: Promotion Reviewer
  • Next Office: PR Synthesist
  • Epistemic posture: mixed — architecture proposal grounded in existing Office doctrine and an external participability test
  • Disposition: promotion candidate

Why this work exists

An external intelligence could orient through Tyme Hall and traverse into repositories, but could not determine a responsible contribution because active institutional work, its current state, and its acceptance boundary were not visible.

Evidence and lineage

  • Existing Office doctrine defines Work as the institutional superclass and requires current state, current Office, next valid action, explicit gates, and recoverable lineage.
  • Existing Branch Lifecycle Doctrine separates branch purpose from lifecycle, authority, disposition, and circulation state.
  • Existing Fabricator Packet Protocol requires bounded authority, observable success conditions, and an evidence-bearing return.
  • The public participability evaluation identified no discoverable task as the exact contribution failure point.

What an external intelligence may contribute now

  • Review the proposed Work/Branch distinction for contradictions with the existing public architecture.
  • Inspect the Branch, Trail Event, and Office Review schemas for missing fields, ambiguity, or authority leakage.
  • Identify any state or relationship required to reconstruct the lifecycle that the current schema cannot represent.
  • Test whether this page itself is sufficient to understand the work without private context.

Acceptance criteria

  • A context-zero evaluator can explain why Work and Branch are distinct.
  • The evaluator can identify current state, current Office, next valid action, evidence sources, and forbidden actions without guessing.
  • The evaluator can propose a bounded correction tied to an observable gap.
  • The contribution can be returned as a GitHub PR/comment or structured evaluation without claiming implementation authority.

Authority boundary

Allowed: inspect, critique, cite evidence, propose schema/document corrections, and return a review.

Not implied: merge authority, Canon promotion, Office reassignment, autonomous execution, Notion mutation, repository settings changes, or expansion into unrelated repositories.
